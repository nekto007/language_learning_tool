# Яндекс Метрика: LLT English

Счётчик **114597985**, домен **llt-english.com** (две буквы l в начале).
`learn.llt-english.com` — другой проект, счётчик туда не подключается.

## Выкладка

По умолчанию production-сайт использует этот счётчик. Менять `.env` не нужно;
`YANDEX_METRIKA_ID=` отключит интеграцию. Миграции и новые зависимости не нужны.

```sh
docker compose build web
docker compose up -d web
```

Метрика отключена на localhost, других доменах, в debug/testing, в админке,
для вошедших администраторов, на API нативных клиентов и чувствительных auth-страницах.
Счётчик работает только по HTTPS. За прокси должен корректно передаваться HTTPS
(проект уже использует ProxyFix).

## Настройки счётчика

- Принимать данные только с указанных адресов: включено, поддомены выключены.
- Автоматические цели, электронная коммерция, тег менеджер: выключены.
- Вебвизор: включён; «Записывать все поля»: выключено.
- Часовой пояс +03:00, тайм-аут визита 30 минут.

Вебвизор в коде разрешён только на выбранных публичных страницах для гостей.
Вход, регистрация и все страницы после авторизации используют `webvisor: false`
и `clickmap: false`. Содержимое страниц аккаунта не записывается.
Автоматическое отслеживание ссылок отключено: передаются только указанные цели.

## Цели

В Метрике → Цели создайте цели типа «Целевое событие» с точным совпадением
идентификатора (в старом интерфейсе «JavaScript-событие»):

| Название | Идентификатор | Когда происходит |
| --- | --- | --- |
| Начал пробное задание | `landing_preview_started` | Взаимодействие с ответом на главной |
| Ответил в пробном задании | `landing_preview_answered` | Первый выбранный ответ, в том числе неверный |
| Перешёл к регистрации из примера | `landing_registration_click` | Нажал регистрацию под примером |
| Начал занятие из стартовой карточки | `study_start_click` | Нажал CTA стартовой карточки |
| Успешно зарегистрировался | `signup_completed` | Сервер создал аккаунт через форму; событие на следующей странице |
| Получил проверку ответа | `learning_answered` | Первый проверенный ответ на странице Grammar Lab или проверенная отправка урока курса |
| Завершил урок курса | `lesson_completed` | Сервер подтвердил завершение через curriculum submit или progress |

`study_start_view` также передаётся как вспомогательное событие показа карточки.
Начальные цели относятся к разным путям: человек может заниматься без пробного
задания или зарегистрироваться напрямую. Это не обязательная единая цепочка.
`learning_answered` передаётся также при поштучной проверке через check-item и
dictation-word. Для курсов с пакетной проверкой возникает при проверке
набора ответов. `lesson_completed` относится к curriculum, а не ко всем видам
занятий, карточкам или чтению. Повторная загрузка готового урока цели не вызывает.

## Проверка после выкладки

В отдельном браузере без входа администратором откройте главную с отдельной
тестовой UTM-меткой, ответьте в примере, перейдите к регистрации. Через Network
проверьте загрузку tag.js и отправку событий в счётчик 114597985. После создания
целей проверьте их через отладчик Метрики. При локальной проверке используем
подмену `ym`, чтобы тесты не отправляли реальные визиты.

Не используйте рабочий аккаунт администратора для проверки: он исключён.
Учебную тестовую учётку исключите в отчёте «Цель: 100 учеников».
Основная метрика 100 активных за неделю остаётся в нашей админке: блокировщики,
отсутствие JS и отключённые cookie приводят к неполным браузерным данным.
