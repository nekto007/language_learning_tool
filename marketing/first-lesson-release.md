# Переход от главной к первому занятию

## Что изменилось

1. На главной — один случайный пример из 10 заданий A1. Английские фразы, русские инструкции, понятное объяснение правильного ответа. Вариант сохраняется на время сессии; повтор не подменяет вопрос.
2. Кнопка под примером сохраняет A1 при регистрации, в том числе после ошибки заполнения формы. Затем предлагается начать занятие из действующего плана. Можно выбрать другой уровень и настройки. Обычная регистрация продолжает работать, ссылки `next` проходят прежнюю проверку безопасности.
3. Приветственное письмо попадает в очередь в той же транзакции, что и новый аккаунт. Существующий scheduler проверяет очередь каждые 30 секунд. Ошибка SMTP не задерживает вход. Есть конечные повторы и восстановление зависших задач, таймаут SMTP — 15 секунд на операцию сокета. Старым пользователям новые приветственные письма не создаются.
4. В админке «Источники регистраций» добавлены этапы до регистрации и таблицы вариантов/источников. Данные локальные, Google Analytics необязателен. Если он настроен, события дублируются в GA4.

## Выкладка через Docker Compose

Из каталога проекта на сервере, после получения нового кода:

```sh
docker compose build web scheduler
docker compose run --rm web flask db upgrade head
docker compose up -d web scheduler
```

Миграция `20261115_landing_signup_flow` добавляет только таблицы `landing_visits` и `welcome_email_queue` с индексами. Она не меняет существующие уроки и прогресс. Код регистрации требует новой таблицы очереди, поэтому миграцию выполнить до запуска нового web. Новые внешние сервисы, ключи, Redis и Celery worker не требуются. Импорт JSON, перенос MP3 и очистка учебного кеша не нужны.

В текущем Dockerfile web также выполняет миграции при старте; отдельная команда выше делает этот шаг явным до запуска обоих сервисов. `restart` без пересборки образов не обновляет код, который COPY добавляет в контейнер.

## Проверка после выкладки

1. Открыть главную без авторизации, выполнить пример, нажать «Попробовать ещё раз». Ответ и объяснение должны соответствовать той же фразе. Для другого случайного примера открыть новую приватную сессию; обновление страницы сохраняет текущий вариант.
2. Нажать «Перейти к бесплатным урокам». Адрес содержит `level=A1&entry=preview`. Ошибка заполнения формы не должна терять эти параметры.
3. Зарегистрировать тестовый аккаунт: сразу появляется предложение начать A1, рядом «Изменить уровень и настройки». Проверить и начало, и смену уровня. При доступных уроках открывается занятие из текущего плана с его исходными параметрами; если материалов нет — личный кабинет.
4. Убедиться, что регистрация не ждёт письма. Scheduler обычно начнёт отправку на ближайшем 30-секундном проходе. При большом хвосте очереди или проблемах SMTP доставка займёт дольше.
5. Проверить админку → «Источники регистраций»: появились новая сессия, первый ответ, открытие формы и регистрация. После обновления и повторов ответа счётчик этой сессии не увеличивается. Тестовый аккаунт учитывать отдельно от настоящего набора.

Проверить, что scheduler работает:

```sh
docker compose ps
docker compose logs --tail=100 scheduler
```

Если scheduler выключен, аккаунты всё равно создаются, письма остаются в очереди. После пяти неудачных попыток задача получает статус `failed`. При необходимости состояние можно посмотреть в БД:

```sql
SELECT status, count(*) FROM welcome_email_queue GROUP BY status;
```

При аварии сразу после принятия письма SMTP-сервером, но до подтверждения в БД, возможна повторная доставка. Это ограничение фоновой SMTP-отправки; одновременные scheduler-процессы одну активную задачу не забирают.

## Как читать новые цифры

Единица — анонимная браузерная сессия, не уникальный человек и не учебный урок. Открытие фиксируется ответом сервера и может включать автоматические запросы. Вариант, первый ответ и действия привязаны к этой сессии; повторный ответ не переписывает результат первого. Не сохраняются IP-адрес, email в событиях или текст выбранного ответа. После регистрации сессия связывается с созданным аккаунтом.

Период в админке отбирает когорту по первому открытию главной. Последующие действия относятся к той же когорте. Последовательная цепочка требует наблюдаемых этапов в нужном порядке; отдельно показаны все регистрации этой когорты, включая другие кнопки. Открытие формы после возврата к примеру засчитывается после ответа. При очень быстром переходе и задержке сети запрос ответа может прийти после формы — такую цепочку отчёт не дорисовывает. При отсутствии знаменателя отображается «—».

Начало примера — первый фокус на варианте либо первый ответ. Счётчик первого ответа и нажатие перехода не увеличиваются при повторных попытках. Локальное событие отправляется с CSRF-токеном, навигацию не задерживает; сетевой сбой не мешает выполнить пример или зарегистрироваться.

Источники берутся из существующей первой UTM-атрибуции сессии, не из присланных браузером параметров события. Для самостоятельной проверки нового источника нужна новая приватная сессия. Исторические действия до выкладки не восстанавливаются.

GA4 при наличии настройки получает `landing_preview_started`, `landing_preview_answered`, `landing_registration_click`; существующее `signup_completed` теперь содержит уровень и `entry_point`. Идентификатор примера одинаковый в локальной таблице и GA4. Для локального отчёта GA4 не требуется.
