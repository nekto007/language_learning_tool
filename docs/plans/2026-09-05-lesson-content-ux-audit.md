## Как читать и что считать «уроком»

Все 86 модулей построены одним генератором по одной раскладке (18 уроков в одном порядке, одинаковые схемы контента), поэтому «побренштормить каждый урок» = разобрать **каждый из 17 типов** по всем 86 инстансам сразу, а отклонения отдельных модулей вынести в «Выбросы». Ручной A1_1 показывает, каким владелец видит хороший урок, — там, где генератор от него отступил, это записано как находка.

Шкала: **P1** — пользователь сталкивается регулярно, и это мешает учиться; **P2** — заметный дефект качества; **P3** — полировка. Объём правки: **K** — контент (JSON + SQL на прод, по координатам, не по id), **T** — шаблон/роут (одна правка на все 86), **K+T** — оба.

Чекбоксы под каждым пунктом: `[ ] Codex` (перепроверил или вписал возражение) · `[ ] Апрув` (владелец) · `[ ] Код/Контент` · `[ ] Страж` · `[ ] Ревью`.

## Часть A — сквозные находки

### A1. Пять уроков модуля на одних и тех же 20 предложениях — P1 · K

- [ ] Codex · [ ] Апрув · [ ] Контент · [ ] Страж · [ ] Ревью

**Что видит пользователь.** Предложение «I have many relatives in this city.» из словаря (урок 1) он встречает в матчинге (урок 3), в аудио-пропусках (урок 9), в теневом чтении (урок 10) и, с вероятностью 42 %, в диктанте (урок 11). Модуль ощущается как одно упражнение, размноженное по формам.

**Факты (скан 86 JSON, совпадение по нормализованному тексту с `vocabulary[].example`).** `collocation_matching.pairs.phrase` — 1 444/1 684 (85 %); `audio_fill_blank.items` с подставленным ответом — 1 375/1 658 (82 %); предложения `shadow_reading.text` — 1 065/1 418 (75 %); предложения `dictation.audio_text` — 119/279 (42 %). В A1_1 (эталон) переиспользования нет.

**Предложение.** Для каждого типа завести свой источник: матчинг — настоящие сочетания 2–3 слова (см. B3, есть `content/vocabulary/collocations.csv`, но там 85 строк — нужен генератор по модулю); теневое чтение — связный мини-текст 5–7 предложений на тему модуля (см. B10); аудио-пропуски — новые предложения с теми же словами, не примеры словаря (см. B9). Диктант — 42 % допустимо оставить, если фраза короткая.

**Страж.** Скан-скрипт из «Замеров» в `tests/test_module_content_quality.py`: доля переиспользования ≤ 20 % на тип.

**Вопрос владельцу.** Это самая дорогая правка (контент 85 модулей × 3 типа). Делать целиком или сначала A1–A2, где пользователей больше?

### A2. Четыре типа показывают всё сразу — P1 · T

- [ ] Codex · [ ] Апрув · [ ] Код · [ ] Страж · [ ] Ревью

**Что видит пользователь.** Матчинг: две колонки по 20 карточек, на телефоне — прокрутка туда-сюда, пока ищешь пару. Аудио-пропуски: один мастер-клип на 60–90 секунд, потом 20 вопросов. Дополнение и перевод: 12–15 полей ввода на одной странице, «Проверить» внизу.

**Факты.** `collocation_matching.html` — два цикла `for pair in pairs` / `shuffled_pairs`, пагинации нет (медиана 20 пар, только A1_1 — 6). `audio_fill_blank.html` — все `items` под одним мастер-аудио, пункты разблокируются после прослушивания (`afb-items--locked`); клип на пункт есть у 245/1 658 (15 %, почти весь — A1_1). `sentence_completion.html` — один цикл по 12–15 `items`. `translation.html` — 12–15 полей, проверка per-item, 3 попытки. Квизы (`quiz.html`, `final_test.html`) при этом уже по одному вопросу с «Далее» — подача внутри одного модуля непоследовательна.

**Предложение.** Общий паттерн «раунды по N с кнопкой «Далее» и прогрессом X из Y» для четырёх шаблонов: матчинг — раунды по 5–6 пар (как в A1_1); аудио-пропуски — по 5 пунктов на экран, у каждого свой клип (см. B9); дополнение и перевод — страницы по 5. Ответы страницы проверяются на месте, итог — после последней. Тело POST не меняется (списки `answers`/`user_pairs` — те же).

**Страж.** Рендер-тесты шаблонов: 20 пар → 4 раунда, в DOM видим только текущий; 15 переводов → 3 страницы.

### A3. Перевод грейдится точным совпадением без альтернатив — P1 · K+T

- [ ] Codex · [ ] Апрув · [ ] Код/Контент · [ ] Страж · [ ] Ревью

**Что видит пользователь.** «He's my distant relative» → неверно, потому что эталон «He is a distant relative of mine.». Три попытки сгорают на синонимах и сокращениях.

**Факты.** `grade_translation` → `_strict_text_match` (точное совпадение после нормализации), `grade_translation_multi` принимает `alternatives`, но у **всех** 1 154 заданий `translation` ровно одна альтернатива — сам ответ. В `translation_quiz` `acceptable_answers` ≤ 1 у A1 25 %, A2 14 %, B1 53 %, B2 57 %, **C1 78 %** — чем выше уровень и вариативнее язык, тем строже. «Дополнительные задания» финального теста — те же переводы (189 из 210 заданий в 70 секциях).

**Предложение.** (K) 2–4 альтернативы на задание (сокращения, синонимы, порядок слов) — генерируемо по правилам + ручная выборка; (T) грейдер: нормализация сокращений (`he's`↔`he is`), опциональные артикли/финальная пунктуация, Левенштейн ≤ 1 на слово ≥ 4 букв (как в `grading.py` для fill-blank), режим `rubric` (C1) — мягкий скоринг по ключевым словам вместо бинарного.

**Страж.** Таблица кейсов в `tests/curriculum/test_grading.py`: contraction, missing article, 1-typo, wrong word → ожидаемый вердикт.

### A4. Нет объяснения после неверного ответа — P2 · K

- [ ] Codex · [ ] Апрув · [ ] Контент · [ ] Страж · [ ] Ревью

**Факты.** Пустой `explanation`: `dialogue_completion_quiz` 333/840, `translation_quiz` 329, `reading` 305, `final_test` 227, `listening_quiz` `translation` 76. В A1_1 объяснения есть везде.

**Предложение.** Сгенерировать объяснения по шаблону типа («Правильно: X — потому что …») с ручной выборкой по 10 на уровень; в шаблонах ничего менять не надо — поле уже рендерится в разборе.

### A5. Правильный вариант — самый длинный — P2 · K

- [ ] Codex · [ ] Апрув · [ ] Контент · [ ] Страж · [ ] Ревью

**Факты.** В диалогах у 631/843 (75 %) правильный ответ длиннее всех дистракторов; в MC чтения — 176/272 (65 %). Дистракторы часто абсурдны («No, I hate all fashion.», «I don't like cake.»).

**Предложение.** Выровнять длину дистракторов (±30 % от правильного), сделать их правдоподобными (одна и та же грамматическая форма, соседняя лексика). Страж: доля «самый длинный = правильный» ≤ 35 % на тип.

### A6. Артефакты генератора видны пользователю — P2 · K

- [ ] Codex · [ ] Апрув · [ ] Контент · [ ] Страж · [ ] Ревью

**Факты.**
1. `sentence_completion.items[].context = "vocab use"` — 734 задания в 58 модулях; шаблон рендерит `context` строкой над полем (`sentence_completion.html:32-35`) → пользователь читает «vocab use».
2. 23 заголовка модулей заканчиваются точкой, и 414 заголовков уроков собираются из них: «Карточки: Семейные отношения. (повторение)», «Словарь: Мода и образ жизни.».
3. Чек-листы письма на двух языках в одном списке у 68/86 («Used at least 3 concrete examples» рядом с «Использован академический регистр»).
4. `sentence_completion.instruction` пуст у 72/86; в A1_1 он есть, но не про то: «Вставьте недостающую форму глагола BE», а первый ответ — `hello`.
5. Заголовки секций финального теста на двух языках (488/806 «Раздел 1: Vocabulary») — пользователю **не видны** (стартовый экран показывает только число вопросов), только гигиена.
6. `duration_seconds = 0` у 12 диктантов и 12 аудирований — шаблоны читают `audio.duration`, поэтому не видно; гигиена.

**Предложение.** Один SQL/скрипт: очистить `context` со значением `vocab use`, снять точки в заголовках модулей и пересобрать заголовки уроков, привести чек-листы к русскому, написать `instruction` под `mode` дополнения (`''`→«Впишите слово из словаря модуля», `collocation`→«Подберите слово, которое сочетается…», `transformation`→«Измените форму…»).

### A7. Подсказки включены всегда и одинаковы на всех уровнях — P2 · K+T

- [ ] Codex · [ ] Апрув · [ ] Код/Контент · [ ] Страж · [ ] Ревью

**Факты.** Дополнение: `hint` = первая буква + длина («r•••••••») стоит в `placeholder` поля у 100 % заданий, на C1 тоже. Перевод: «Показать опорные слова» раскрывает **все** слова ответа (перемешаны, некликабельны) — `hint_words` совпадают с токенами ответа у 1 154/1 154; для режима `open` («перевод с минимальной опорой — для B1+») это противоречие с собственной подписью.

**Предложение.** Дополнение: подсказка по кнопке «Подсказка» (A1–A2 — сразу первая буква, B1+ — только по кнопке, C1 — только длина). Перевод: `hint_words` = 2–3 ключевых слова (K), кнопка остаётся.

### A8. Внутри типа нет прогрессии от A1 к C1 — P2 · T+K

- [ ] Codex · [ ] Апрув · [ ] Код/Контент · [ ] Страж · [ ] Ревью

**Факты.** Диктант несёт `mode ∈ {cloze 52, sentence_reconstruction 12, full_dictation 11, phrase_cloze 11}`, но ни `dictation.html`, ни роут (`_dictation_items_from_content` читает только `hint_chars`) режим не используют: C1 «full_dictation» — те же 4–5 пропусков с первой буквой, что A1 cloze. `hint_chars` = 0 у 13 уроков и 1 у 73 без связи с уровнем. Матчинг, аудио-пропуски, порядок слов — одинаковое число заданий на всех уровнях.

**Предложение.** Реализовать режимы диктанта (`full_dictation` — ввод всего предложения, `sentence_reconstruction` — слова вразброс), политика `hint_chars` по уровню (A1–A2 1, B1+ 0). Число заданий по уровню в A2/B9 задавать константами уровня, а не одним числом.

### B4. `grammar` — 86 уроков, теория

### B5. `sentence_completion` — 86 уроков, 12–15 заданий

**Как работает.** Список заданий «начало — [поле] — конец», подсказка в placeholder, «Проверить» внизу, потом разбор. Три режима в контенте: `''` 734 (вставить слово словаря), `collocation` 191, `transformation` 196.

### B6. `reading` — 86 уроков, текст построчно + 5–11 вопросов

- [ ] Codex · [ ] Апрув · [ ] Код/Контент · [ ] Страж · [ ] Ревью

## Замеры — как воспроизвести

Все числа сняты 2026-09-05 на копии прода (`docker exec language_learning_tool_db psql -U igor_adm -d learn_db_prod`) и JSON из `module_completed/fixed/`.

```sql
-- размеры на тип (пример: пары матчинга)
select min(n), percentile_cont(0.5) within group (order by n), max(n)
from (select jsonb_array_length(content::jsonb->'pairs') n from lessons where type='collocation_matching') s;
-- строгость перевода
select count(*) filter (where coalesce(jsonb_array_length(e->'alternatives'),0) <= 1), count(*)
from lessons, jsonb_array_elements(content::jsonb->'items') e where type='translation';
-- «самый длинный = правильный»
select count(*) filter (where length(e->>'correct') = (select max(length(o)) from jsonb_array_elements_text(e->'options') o)), count(*)
from lessons, jsonb_array_elements(content::jsonb->'exercises') e where type='dialogue_completion_quiz';
-- артефакт vocab use
select count(*) from lessons, jsonb_array_elements(content::jsonb->'items') e
where type='sentence_completion' and e->>'context'='vocab use';
```

Переиспользование предложений: для каждого модуля множество нормализованных `vocabulary[].example`; совпадение по нему `collocation_matching.pairs.phrase`, `audio_fill_blank.items` (с подставленным `answer`), предложений `shadow_reading.text` и `dictation.audio_text` (нормализация: нижний регистр, только буквы/цифры/пробелы). Скан-скрипт — в scratchpad сессии, логика описана здесь целиком; при реализации стража переносится в `tests/test_module_content_quality.py`.
