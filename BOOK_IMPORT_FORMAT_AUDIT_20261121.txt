CONFIRMED FINDING 1: SHARED SERVER TEMP FILENAME
Location: app/admin/services/book_processing_service.py:87-95, save_uploaded_book_file.
Current behavior: target_path joins common BOOK_TEMP_DIR with secure_filename(original filename).
Safe reproduction: two FileStorage objects named same.txt, saved sequentially inside a TemporaryDirectory, return the exact same path. Reading the first returned path after the second save returns SECOND_SYNTHETIC_BOOK. The subsequent request cleanup can also remove another request's input.
Current exposure: admin-only /admin/books/extract-metadata and add-book routes use this helper; no ordinary-user upload access was found. This is a real concurrent-import data-integrity/isolation defect, not a demonstrated anonymous exploit.
Recommended bounded fix: allocate a unique temporary path with mkstemp or UUID plus validated extension; keep the separately returned safe original filename for display only; clean partial file on failed save. Regression must preserve both same-name request contents and verify failure cleanup.
Related safer path: app/books/parsers.py:609 already uses mkstemp for process_uploaded_book.

CONFIRMED FINDING 2: SERVER EPUB EXPANSION HAS NO APPLICATION BUDGET
Locations: app/books/parsers.py:295 and :417 call ebooklib.epub.read_epub directly.
Installed implementation examined: ebooklib EpubReader._load_manifest reads every manifest item via ZipFile.read, including images/fonts/binary items not used in the text renderer. ZIP64 is enabled. The application currently has no entry-count, per-entry-expanded or cumulative-expanded preflight at these calls.
Safe reproduction: a 2104-byte, valid synthetic EPUB with one tiny chapter and one unused 1048576-byte repetitive binary manifest item loads the entire unused resource in memory. No large archive or resource-exhaustion test was run.
Current exposure: admin-only metadata and content import. Global MAX_CONTENT_LENGTH is 16MiB and the reusable admin upload helper permits 50MiB; neither bounds decompressed ZIP resources.
Recommended bounded fix: before both EPUB metadata/content calls, validate archive entry count and safe normalized names; reject duplicates, traversal, encryption and unsupported compression; enforce explicit per-entry and cumulative expanded-byte budgets and bounded actual reads. Do not rely solely on compression ratio (legitimate text compresses well). Avoid silent TXT fallback when the archive is rejected. Retain current public/admin restriction until ownership and limits are designed for any future personal upload.
No ZIP-slip write was found: current Python EPUB path uses ZipFile.read, not extract/extractall; the iOS ZIP reader never extracts files at all. Lack of Python archive preflight is primarily a resource-budget concern here.

CONFIRMED BEHAVIOR 3: LEGACY SERVER XML IS LESS STRICT THAN IOS
Locations: app/books/parsers.py:224/:360 and convert_fb2_to_txt.py:54 use stdlib ElementTree.
Safe reproduction: a single small internal entity expands to SYNTHETIC_EXPANSION in FB2 body/metadata. External-file entity containing only a synthetic sentinel is not resolved; parser raises undefined entity and parse_fb2 falls back to TXT. No local-file disclosure was observed.
Installed EbookLib XML helper explicitly sets resolve_entities=False; no external entity request was observed in the synthetic EPUB check.
Assessment: not claiming XXE or an exploitable exponential bomb. The existing server does not adopt iOS's explicit reject-all-declarations policy; future untrusted import should use an explicit hardened XML policy and fail closed, without interpreting rejected XML as a book of raw markup. Cover binary decoding also has no dedicated decoded-image budget in extract_fb2_cover, beyond the uploaded raw file limit.

IOS EXISTING BOUNDS AND VERIFIED DEFENSES
BookFileImporter.parse: raw data <=20000000 bytes, nonempty; extension dispatch TXT/FB2/EPUB.
File picker checks file size before Data(contentsOf:) when provided and checks Data size afterward. A provider with missing/misreported size can still allocate the data before the second check; no reproducible harmful provider was exercised. A bounded stream read would be additional hardening, not an established ordinary-file bypass.
XMLParser: external resolution disabled and .never policy; internal/external entity declarations abort parsing; resolving delegate returns nil.
EPUB archive: <=5000 entries; normalized names, no absolute/backslash/colon/NUL, traversal rejected; duplicate normalized names rejected; no filesystem extraction. Unsupported/encrypted used entries rejected; CRC and declared-expanded length checked.
Read budget: <=8000000 expanded bytes per used entry and <=40000000 cumulative read bytes; fixed bounded decompression allocation. XML <=40000000 bytes; spine <=2000 entries; generated readable text <=40000000 bytes, paragraph <=500000 bytes, <=2000 output chapters. Title/author trimmed to300 characters.
Fonts may be obfuscated but are not read/rendered; supported font obfuscation is intentionally distinguished from text DRM.
No confirmed parser security defect requiring an iOS source change in this audit.

PRIVACY BOUNDARY: EXPLICIT WORD TRANSLATION IS A SERVER REQUEST
Importing/reading a personal book does not upload the whole book. ReaderTranslationController.swift:172-175 nevertheless sends ContextualLookup when signed in and online, including selected text, the containing sentence, lemma and selection offsets. ContextualLookup excludes local filename, book title and localID.
Endpoint app/api/native_translation.py:/reader/lexicon is authenticated/rate-limited/private-response. app/reader_translation/service.py validates bounded strings and queries dictionary/expression candidates; inspected service does not persist the sentence or call a remote model. This is a real intentional selected-excerpt transfer, not an automatic upload or a demonstrated cross-user disclosure.
Saving a word/context is separately account-scoped sync: imported contexts can include book title/localID and a bounded sentence. Backend agent owns full owner-scope verification. Any UI promise that a book or its excerpts 'never leave this iPhone' must distinguish local full-file import from explicit lexical lookup and word synchronization.
Legacy server metadata/import logs include book title/author/temp path (app/books/parsers.py and book_processing_service.py). These admin catalog logs are not a demonstrated other-user data leak; do not reuse that logging unchanged for future private manuscripts.
