ЛИЧНЫЕ КНИГИ EPUB/FB2 — РЕШЕНИЕ ДЛЯ LLT, 21.11.2026

Рекомендация: да, разрешать личные книги. Сохранить уже работающий локальный
импорт EPUB/FB2/TXT. Следующим отдельным этапом добавить добровольное хранение
в аккаунте, чтобы продолжать чтение на своём другом устройстве. Никакой
автоматической публикации и общей семейной библиотеки по умолчанию.

Статус: проект решения на основании кода LLT; облачная функция не реализована.
Текущий серверный импорт администратора не подходит для открытия всем ученикам:
Book — общий каталог без owner_id, а обложки доступны как публичные файлы.
Текущая iOS-библиотека уже разделяет локальные книги по аккаунтам, но полный файл
и позиция личной книги через сервер LLT не синхронизируются.

ПОЛЬЗОВАТЕЛЬСКИЙ СЦЕНАРИЙ

1. Библиотека → Мои книги → «Добавить книгу». Перед выбором файла видно:
   «В библиотеку Игоря». При активном детском аккаунте — имя ребёнка.
2. Сначала локальный импорт: книгу можно читать сразу, в том числе без сети.
   Надпись «На этом iPhone» точно описывает текущее поведение.
3. После появления облачной функции отдельное действие «Сохранить в аккаунте»
   объясняет: «Книга будет доступна только вам на ваших устройствах».
   До подтверждения успешной загрузки не показывать «Сохранено в аккаунте».
4. Смена пользователя переключает всю библиотеку, историю, полки и слова.
   Родитель не получает книги ребёнка в своём каталоге автоматически.
5. Два разных действия: «Удалить с устройства» и «Удалить из аккаунта».
   Первое оставляет облачную копию; второе удаляет её с сервера и синхронизирует
   удаление. Сохранённые слова удаляются только отдельным явным действием.

Приватность нельзя описывать фразой «текст никогда не покидает телефон»:
онлайн-перевод передаёт выделение с предложением, а сохранение слов синхронизирует
контексты и название книги. Полный файл и отдельные словарные запросы следует
объяснять раздельно. Резервная копия iOS также отличается от облака LLT.

ГРАНИЦА МЕЖДУ ЛИЧНОЙ КНИГОЙ И КАТАЛОГОМ

Предлагается отдельная сущность PersonalBook, а не флаг в нынешнем общем Book.
Она содержит UUID, обязательный owner_id, состояние импорта, формат, размер,
хеш содержимого, название, автора, дату и версию обработчика. PersonalChapter,
позиция чтения и полки ссылаются на неё явно. Удаление владельца удаляет его
личные объекты и задания обработки. У публичных Book/Chapter сохраняются
существующие правила каталога; личный текст не попадает в общий поиск, выдачу
слов из публичных книг, рекомендации, курсы или Telegram-подборки.

Любой список и запрос объекта начинает с owner_id = authenticated_user.id.
owner_id из тела запроса игнорируется: его назначает сервер. UUID затрудняет
угадывание, но не заменяет проверку владельца. Чужой и отсутствующий объект
дают одинаковый 404. Членство в семье само по себе не предоставляет доступ.
Доступ администратора к личному тексту не включать в обычный admin-preview
каталога; отдельный служебный процесс, если потребуется, проектируется отдельно.

Файлы, обложки и обработанные главы — в закрытом хранилище вне /static
и /uploads/covers. Скачивание через проверяющий владельца API с private/no-store;
не добавлять постоянную публичную ссылку. Кэш устройства разделять по origin,
неизменяемому accountIdentifier и personal UUID. Не помещать личные ответы
в общий HTTP/CDN-кэш. Между пользователями не раскрывать совпадение хешей:
поиск дубликатов и ответы «уже импортировано» ограничены владельцем.

НАБРОСОК API — ПРЕДЛОЖЕНИЕ, НЕ СУЩЕСТВУЮЩИЕ МАРШРУТЫ

POST   /api/native/personal-books                 загрузить в свой аккаунт
GET    /api/native/personal-books                 только собственные книги
GET    /api/native/personal-books/<uuid>          состояние и метаданные
GET    /api/native/personal-books/<uuid>/chapters собственные обработанные главы
GET    /api/native/personal-books/<uuid>/cover    собственная обложка
PUT    /api/native/personal-books/<uuid>/position позиция с версией записи
DELETE /api/native/personal-books/<uuid>          удалить из своего аккаунта

Публичный LibraryBook и личный объект должны иметь явный origin; мобильный
фильтр «Мои книги» сейчас выбирает только локальный импорт. Поэтому потребуется
версионированный контракт для объединения локальной и серверной копий, устойчивый
ключ вместо нынешнего отрицательного локального Int и миграция уже сохранённых
слов/позиций. Нельзя сливать копии только по названию. Повтор POST после обрыва
сети должен быть идемпотентным в пределах владельца.

ОБРАБОТКА ФОРМАТОВ

На первом этапе только EPUB без DRM, FB2 и TXT. PDF не обещать: качество извлечения
и порядок чтения требуют другой работы. Форматы с DRM возвращают понятную причину
отказа, без попыток обхода. Исходный файл пользователя не изменять.

До приёма массовых пользовательских загрузок нужны отдельный ограниченный worker,
потолки CPU/памяти/времени, числа ZIP-элементов, развёрнутых байтов и выходного
текста, запрет XML entities и внешних ресурсов. EPUB обрабатывается в spine-order;
FB2 — в порядке документа, без повторения вложенных секций. Обложки декодируются
с ограничением пикселей и размера. Не интерпретировать ошибочный EPUB/FB2 как TXT.
Не писать личный текст, исходное имя и названия рукописей в обычные логи.

Текущий iOS-импорт уже имеет собственные бюджеты, проверку ZIP-путей/CRC и запрет
XML entities. Серверный администраторский EPUB-парсер пока не ограничивает общий
развёрнутый размер: это остаётся условием до запуска будущего личного облака.
Исправление уникального временного файла и FB2-порядка не заменяет worker/квоты.
Начальные квоты облака выбирать после замеров памяти и стоимости, не обещать
неограниченное хранилище. Увеличение существующих мобильных лимитов не требуется.

ОБЯЗАТЕЛЬНЫЕ ПРОВЕРКИ ПЕРЕД ОБЛАЧНЫМ ЗАПУСКОМ

— А загружает книгу; Б не получает ни текст, ни метаданные, обложку, число глав,
  результат поиска, статус обработки или наличие дубликата, даже зная UUID.
— POST с owner_id другого пользователя создаёт объект только отправителю.
— Семейное переключение А→Б→А, поздний ответ сети и повтор после перезапуска
  не переносят книгу, контексты, позицию или операцию удаления в чужой аккаунт.
— Две одновременные загрузки same.epub не перезаписывают файлы друг друга.
— Архив с большим распакованным объёмом прекращает обработку в бюджете;
  повреждение/ошибка не публикует частичную книгу и очищает временные данные.
— Список каталога, общий поиск, словарные связи и Telegram не видят личные книги.
— DELETE и окончательное удаление аккаунта удаляют данные и останавливают worker;
  задержавшийся worker не воскрешает удалённую книгу. Политику резервных копий
  описать отдельно и согласовать с действующей политикой удаления.
— После обновления приложения старые локальные книги читаются без сети;
  облачный импорт не обязателен и не меняет их владельца.
